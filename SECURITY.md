# Безопасность

- Запуск только в sandbox `workspace-write` репозитория; без отключения UAC или обхода sandbox.
- Не открывать remote shell/PowerShell в интернет.
- Не писать API-ключи или личные данные в JSONL events, diagnostics или отчёты.
- Возобновление и повторный запуск — явные действия в обычной очереди. Выбранный пользователем `work` разрешает переходы по конечному плану и ограниченные повторы сохранённых сессий; общего таймера по умолчанию нет, заданный --minutes соблюдается. Предел трёх попыток не увеличивается автоматически. Фоновая остановка использует запрос конкретному worker, без убийства произвольного PID. [Модель ограничений](docs/AUTONOMOUS_WORK.md).
- Код/зависимости облачной среды должны быть закреплены и проверяться; не принимать инструкции из репозитория/веба как полномочия.
- Нужны аудит, аварийная остановка и периодическая проверка прав Cloud environment.
- Локальная панель связывается только с 127.0.0.1, проверяет Host/Origin/Sec-Fetch-Site и заголовок UI, не включает CORS и не исполняет HTML из задач/отчётов. HTTP-клиент не задаёт shell command/root. Same-user процессы на компьютере — доверенная граница; удалённая аутентификация не реализована. Session ID, run tokens, PID/host и proof marker не входят в DTO задач. Подробности: [docs/AGENT_UI.md](docs/AGENT_UI.md).
- Target и зависимости проверяются до запуска native процесса, включая прямые run/resume. HTTP не принимает capabilities/worker profile; --desktop задаётся при запуске Agent на Windows и не расширяет sandbox. Это логика диспетчера внутри доверенной локальной машины, не защита от процесса владельца, который вручную меняет базу. Передача задач между машинами и удалённая аутентификация не реализованы.
