# Переносимый пакет для Windows x64

Пакет содержит локальную панель Agent, CLI, документацию, проектную память и официальный Node.js 24.22.1. Установка Node.js и клонирование исходников для открытия панели не требуются. Установленный Git и официальный native Codex CLI с существующим входом нужны для реального исполнения задач. Авторизация Codex остаётся у штатного клиента; пакет её не переносит.

## Запуск на ПК

1. Скачайте `SkAi-Agent-win-x64.zip` из проверенной сборки и распакуйте весь архив в отдельную папку.
2. Откройте `chat.cmd` двойным щелчком. Появится локальная панель задач.
3. Добавьте задачу и выберите запуск очереди. Создание задачи само по себе модель не вызывает.

Сохраняйте папку `runtime` рядом с `agent.cmd`. Явный `SKAI_NODE_EXE` имеет первый приоритет, затем выбирается встроенный Node, затем прежний поиск PATH/стандартных папок/Codex runtime. Системный PATH, registry, UAC и установленные приложения launcher не меняет.

При первом исполнении пакет создаёт собственный локальный Git репозиторий в своей папке. Это обычный `git init`, без клонирования, коммита, remote или пропуска проверок Git в Codex. Существующий репозиторий не переинициализируется. Runtime и `.skai-agent` исключены через поставляемый `.gitignore`. Если пакет распакован внутри другого checkout, создаётся собственный Git root; родительский репозиторий не используется как рабочая папка.

В этой версии задачи по-прежнему работают в папке Agent. Это не автоматическое подключение произвольных проектов или Windows-ПК к Cloud. Закрытие браузерной вкладки не останавливает очередь; Ctrl+C в окне запуска останавливает панель и текущую задачу.

## Состояние и обновление

Состояние новой копии находится в её собственной `.skai-agent`. Очереди, сессии и credentials другой установки не импортируются автоматически. Перед обновлением остановите старую панель, распакуйте новую версию в отдельную папку и сохраните старую вместе с её историей. Пакет не удаляет старые каталоги и не переносит неподтверждённые блокировки между машинами.

`START-HERE.txt` содержит краткие инструкции. `BUILDINFO.json` указывает точный commit исходников, версию/источник runtime и закреплённые SHA-256. `FILES.sha256` описывает содержимое архива. Рядом с ZIP сборка сохраняет контрольную сумму самого ZIP.

## Что входит в архив

Builder берёт разрешённые отслеживаемые файлы из точного Git commit, а не произвольное содержимое рабочей папки. Входят launcher, src, тесты, документация, память, схема отчёта и скрипты сборки. `.cmd` нормализуются в CRLF. Из официального Node ZIP берутся только `node.exe` и полный LICENSE; npm не нужен.

Исходные `.git`, `.skai-agent`, node_modules, кеши, логи, неотслеживаемые файлы, известные credential/state файлы и pipeline не включаются. Сборка отказывается маркировать изменённые отслеживаемые файлы как чистый commit и сохраняет изменения. Этот фильтр не заменяет проверку содержимого публикуемых исходников: произвольный секрет нельзя надёжно определить по формату.

Контрольные суммы Node archive, node.exe и LICENSE закреплены в `tools/package_portable.py` после сверки официального `SHASUMS256.txt` по HTTPS. TLS/proxy не отключаются. Runtime скачивается в игнорируемый кеш внутри проекта; каждый повтор проверяет его SHA. Неверный download не заменяет старый кеш. Весь архив не распаковывается вслепую: используются конкретные проверенные файлы.

## Сборка и проверка

Для builder нужны Git и Python 3.9+ со стандартной библиотекой, для первой загрузки runtime — доступ к nodejs.org:

```sh
python3 test/package_portable_test.py
python3 tools/package_portable.py build
python3 tools/package_portable.py verify .skai-agent/dist/SkAi-Agent-win-x64.zip --commit <полный-SHA-текущего-commit>
```

Windows: `python` вместо `python3`. Сборка создаёт `.skai-agent/dist/SkAi-Agent-win-x64.zip` и `.zip.sha256`. Источник остаётся без изменений. Проверка с `--commit` сверяет не только метаданные, но и состав/байты исходников с текущим чистым checkout. Проверка без checkout проверяет структуру, manifest и закреплённые байты Node/LICENSE; она не является цифровой подписью исходников.

Ограничены размер download, распакованный размер и число entries. Запрещены traversal, symlink, специальные имена Windows, case-insensitive дубликаты, неизвестные файлы, шифрование и неожиданные методы сжатия. Стабильные даты/порядок исключают пути машины и текущее время сборки. Побайтовое совпадение ZIP между разными версиями Python/zlib отдельно не предполагается; байты файлов и source commit проверяются явно. Windows job публикует отдельный SHA-256 содержимого FILES.sha256: он позволяет сопоставить все файлы пакета между сборочными машинами независимо от сжатия ZIP.

## CI и границы приёмки

После успешной матрицы Node/Linux/Windows job `portable-windows` проверяет Python regressions, строит пакет, сверяет исходный commit, распаковывает в папку с пробелами и `&`, запускает настоящий bundled Node через launcher без Node/Codex в PATH и проверяет собственный Git root. Затем открывает paused HTTP UI, читает state/memory, убеждается в пустой новой очереди и останавливает процесс. Установки ПО, входа Codex, GUI браузера и вызовов модели здесь нет.

Артефакт `skai-agent-portable-windows-x64` хранит ZIP и checksum семь дней. Это сборочный артефакт, не публикация Release и не обновление Cloud environment. Такой тест подтверждает запуск пакета на Windows runner; он не закрывает реальную модельную/GUI приёмку на ПК пользователя.
