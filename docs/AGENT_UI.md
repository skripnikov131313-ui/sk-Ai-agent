# Локальная панель Agent

Панель принимает задачи обычным текстом, сохраняет очередь и показывает состояние, результаты, проверки, изменённые файлы и блокеры. Это первый локальный интерфейс Agent; удалённый доступ с iPhone и внешний Cloud scheduler ещё не реализованы.

## Запуск

Windows: двойной щелчок по `chat.cmd` либо из проекта:

```powershell
.\agent.cmd ui --open
```

Linux: `node src/cli.mjs ui`. По умолчанию сервер слушает только `127.0.0.1:8741`. Если порт занят, задайте `--port 8742`; `--port 0` выбирает свободный порт. `--open` открывает локальную страницу штатным браузером Windows. Держите процесс панели запущенным: закрытие вкладки не останавливает очередь, Ctrl+C в терминале останавливает текущую задачу и сервер. Независимый фоновый запуск Markdown-плана по-прежнему выполняется через `work-start`.

Без запуска Codex можно работать с `agent.cmd ui --paused`: сохранять задачи, читать отчёты и просматривать план. Для текущей Cloud-проверки пользователь отложил сеть и авторизацию; разработка панели и тесты не требуют их изменения.

## Очередь и отчёты

- «Добавить в очередь» сохраняет задачу, без немедленного вызова модели. Черновик текста, выбора среды и зависимости переживает перезагрузку вкладки. Идентификатор отправки предотвращает дублирование при потере подтверждения; изменённый текст или требования получают новый идентификатор.
- «Где выполнять» выбирает текущую среду, Windows или Windows с рабочим столом. «После задачи» задаёт предшественника, который должен завершиться успешно. Недоступные задачи сохраняются в waiting без попыток; причина видна в карточке. Доступные независимые задачи продолжаются. [Требования, CLI и границы маршрутизации](TASK_ROUTING.md).
- «Выполнить очередь» фиксирует весь текущий список ожидающих задач и выполняет их последовательно без подтверждения между успешными задачами. Новые пользовательские задания остаются для следующего явного запуска. Общего таймера нет; попытка ограничена десятью минутами, всего до трёх попыток на задачу.
- Сохранённая сессия автоматически продолжается после timeout или явного failed-отчёта без blockers, пока остаются попытки. При блокере, отсутствии корректного отчёта или исчерпании попыток запуск прекращается. Это предотвращает повторение проблем с авторизацией/квотой и выполнение зависимых заданий после ошибки.
- «Остановить» прерывает текущий native child и сохраняет interrupted; следующие задания остаются queued. «Продолжить сохранённую задачу» явно выбирает её сессию. Completed повторно не запускается.
- «Восстановить после сбоя» требует остановленные известные PID на той же машине. Живой процесс, неизвестный PID и другой host не считаются остановленными. Нельзя принудительно снять их lock через интерфейс.
- «Рабочий план» показывает этапы текущего `work` в режиме просмотра. Его отдельная очередь не смешивается с заданиями панели и не запускается кнопкой личной очереди.
- Обычный отчёт сообщает исполнитель. Сохранённая файловая приёмка `smoke` отдельно показывает факт проверки контрольного файла; marker и native session ID в API не передаются.

Основная очередь — `.skai-agent/tasks.json`; batch checkpoint хранится в той же базе. Существующие `add/list/show/run/resume` используют эти же задачи. Атомарная запись и блокировки сохраняются. После перезапуска панели задачи читаются из базы, а не из памяти браузера. Credentials не хранятся в клиенте; CLI использует свою штатную авторизацию/квоту.

## Границы интерфейса

HTTP API привязан к буквальному loopback host и проверяет Origin, Sec-Fetch-Site и специальный заголовок UI. Запросы сторонних страниц и DNS rebinding отклоняются; CORS не включён, встраивание во frame запрещено. Тексты задач и отчётов выводятся через textContent, без HTML/Markdown-исполнения. Статические адреса фиксированы, API не принимает команды shell, пути корня проекта или произвольные файлы.

Это защита локального интерфейса от веб-контента. Процессы владельца на самой машине находятся в доверенной границе; отдельная удалённая аутентификация не реализована. Публичное размещение и телефонный клиент требуют другого слоя доступа. Узкий viewport Chromium подтверждает адаптивную компоновку, а не доступность с настоящего iPhone.

## Проверки

`node --test test/*.test.mjs` выполняет HTTP/store/runner integration tests без модели, включая запуск настоящего CLI панели, последовательную очередь, freeze snapshot, stop, resume, recovery, отказ чужому host, CSRF/Host проверки, ограничения тела, idempotency, redaction и сохранение повреждённой базы.

При установленном Python Playwright можно выполнить:

```sh
python3 test/ui-browser.py --browser /usr/bin/chromium --output /workspace/artifacts/agent-ui
```

Проверяются реальные Chromium desktop/mobile страницы, создание/исполнение тестовой очереди, ожидание Windows, автопереходы по зависимостям, отчёты, блокер, потеря подтверждения отправки, перезагрузка черновика, XSS-текст и диалог. Executor — protocol fixture; модель не вызывается. Node-only CI не устанавливает браузерные зависимости. Проверка настоящего Codex через панель остаётся отдельной приёмкой после устранения внешнего блокера.
