# Локальная панель Agent

Панель принимает задачи обычным текстом, сохраняет очередь и показывает состояние, результаты, проверки, изменённые файлы и блокеры. Это первый локальный интерфейс Agent; удалённый доступ с iPhone и внешний Cloud scheduler ещё не реализованы.

## Запуск

Windows: двойной щелчок по `chat.cmd` либо из проекта:

```powershell
.\agent.cmd ui --open
```

Linux: `node src/cli.mjs ui`. По умолчанию сервер слушает только `127.0.0.1:8741`. Если порт занят, задайте `--port 8742`; `--port 0` выбирает свободный порт. `--open` открывает локальную страницу штатным браузером Windows. Держите процесс панели запущенным: закрытие вкладки не останавливает очередь, Ctrl+C в терминале останавливает текущую задачу и сервер. Независимый фоновый запуск Markdown-плана по-прежнему выполняется через `work-start`.

Без запуска Codex можно работать с `agent.cmd ui --paused`: сохранять задачи, читать отчёты и просматривать план. Для текущей Cloud-проверки пользователь отложил сеть и авторизацию; разработка панели и тесты не требуют их изменения.

## Выбор проекта

Список «Рабочий проект» переключает панель между Agent и явно зарегистрированными Git репозиториями. Регистрация выполняется владельцем на той же машине, без сетевых запросов Git:

```sh
node src/cli.mjs projects add browser /workspace/sk-Ai --name "Sk/Ai Browser"
node src/cli.mjs projects list
```

Перезапустите панель после изменения списка. В Windows используется та же команда через `agent.cmd`, с полным путём к папке. Репозиторий должен иметь отдельный корень; вложенные/пересекающиеся папки отклоняются. Поддерживается origin GitHub либо локальный репозиторий без origin. Один ID нельзя переназначить другой папке или репозиторию; повторная регистрация той же привязки может изменить отображаемое название.

Проект `agent` сохраняет прежнюю очередь `.skai-agent/tasks.json` и CLI `add/list/show/run/resume/work`. Для остальных проектов задачи создаются и выполняются в панели. Их очереди и отчёты находятся в `.skai-agent/projects/<id>/` внутри Agent; служебная папка не создаётся в целевом продукте. Раздел «Рабочий план» дополнительного проекта пока пуст: CLI `work` не переключается на другой проект. Реестр `.skai-agent/projects.json` локальный и не включается в переносимый пакет; на другой машине пути регистрируются заново.

Зависимости и продолжение сессии действуют только внутри выбранной очереди. Память читается из `MEMORY.json` выбранного корня. Черновики текста, среды, зависимости и идентификатор повторной отправки разделены по привязке проекта в текущей вкладке; переключение и перезагрузка их сохраняют. Поздний ответ старого проекта не обновляет новый экран. Если сохранённая привязка изменилась, панель требует выбрать проект явно, без автоматической отправки в Agent.

Один процесс панели выполняет одну очередь за раз. При переключении во время работы показан активный проект и переход к нему; запуск другой очереди отклоняется. Остановка действует на выбранный проект. Перед каждой native попыткой Agent снова проверяет реестр, канонический Git root, metadata и origin. Изменение привязки не расходует попытку; история сохраняется. База содержит ID/fingerprint проекта: копирование очереди другого проекта не меняет её владельца автоматически.

HTTP принимает только ID из заранее загруженного списка и fingerprint привязки. Произвольные пути, команды, регистрация/переназначение проекта через веб-интерфейс не поддерживаются. Native adapter продолжает использовать `workspace-write` выбранного корня; текущие проверки исполнения дополнительных проектов используют fixture, реальная задача Codex остаётся отдельной приёмкой после отложенной авторизации.

## Очередь и отчёты

- «Добавить в очередь» сохраняет задачу, без немедленного вызова модели. Черновик текста, выбора среды и зависимости переживает перезагрузку вкладки. Идентификатор отправки предотвращает дублирование при потере подтверждения; изменённый текст или требования получают новый идентификатор.
- «Где выполнять» выбирает текущую среду, Windows или Windows с рабочим столом. «После задачи» задаёт предшественника, который должен завершиться успешно. Недоступные задачи сохраняются в waiting без попыток; причина видна в карточке. Доступные независимые задачи продолжаются. [Требования, CLI и границы маршрутизации](TASK_ROUTING.md).
- «Выполнить очередь» фиксирует весь текущий список ожидающих задач и выполняет их последовательно без подтверждения между успешными задачами. Новые пользовательские задания остаются для следующего явного запуска. Общего таймера нет; попытка ограничена десятью минутами, всего до трёх попыток на задачу.
- Сохранённая сессия автоматически продолжается после timeout или явного failed-отчёта без blockers, пока остаются попытки. При блокере, отсутствии корректного отчёта или исчерпании попыток запуск прекращается. Это предотвращает повторение проблем с авторизацией/квотой и выполнение зависимых заданий после ошибки.
- «Остановить» прерывает текущий native child и сохраняет interrupted; следующие задания остаются queued. «Продолжить сохранённую задачу» явно выбирает её сессию. Completed повторно не запускается.
- «Восстановить после сбоя» требует остановленные известные PID на той же машине. Живой процесс, неизвестный PID и другой host не считаются остановленными. Нельзя принудительно снять их lock через интерфейс.
- «Рабочий план» показывает этапы текущего `work` в режиме просмотра. Его отдельная очередь не смешивается с заданиями панели и не запускается кнопкой личной очереди.
- «Память» показывает сохранённые предпочтения, проверенные приёмы и метрики обеих очередей без вызова модели. Каталог применяется к следующим native попыткам; его просмотр не редактирует память или историю. [Формат, применение и ограничения](PROJECT_MEMORY.md).
- Обычный отчёт сообщает исполнитель. Сохранённая файловая приёмка `smoke` отдельно показывает факт проверки контрольного файла; marker и native session ID в API не передаются.
- Статус задачи определяет Agent: корректный отчёт с непустым blockers означает blocked даже при заявленном исполнителем completed. Противоречивый исходный отчёт сохраняется, очередь останавливается, зависимые задания не запускаются.

Основная очередь — `.skai-agent/tasks.json`; batch checkpoint хранится в той же базе. Существующие `add/list/show/run/resume` используют эти же задачи. Атомарная запись и блокировки сохраняются. После перезапуска панели задачи читаются из базы, а не из памяти браузера. Credentials не хранятся в клиенте; CLI использует свою штатную авторизацию/квоту.

## Границы интерфейса

HTTP API привязан к буквальному loopback host и проверяет Origin, Sec-Fetch-Site и специальный заголовок UI. Запросы сторонних страниц и DNS rebinding отклоняются; CORS не включён, встраивание во frame запрещено. Тексты задач и отчётов выводятся через textContent, без HTML/Markdown-исполнения. Статические адреса фиксированы, API не принимает команды shell, пути корня проекта или произвольные файлы.

Это защита локального интерфейса от веб-контента. Процессы владельца на самой машине находятся в доверенной границе; отдельная удалённая аутентификация не реализована. Публичное размещение и телефонный клиент требуют другого слоя доступа. Узкий viewport Chromium подтверждает адаптивную компоновку, а не доступность с настоящего iPhone.

## Проверки

`node --test test/*.test.mjs` выполняет HTTP/store/runner integration tests без модели, включая запуск настоящего CLI панели, последовательную очередь, freeze snapshot, stop, resume, recovery, отказ чужому host, CSRF/Host проверки, ограничения тела, idempotency, redaction и сохранение повреждённой базы. `test/projects.test.mjs` проверяет реестр, scope/binding, отдельные корни/очереди/память, смену origin, защиту скопированной базы и остановку выбранной очереди.

При установленном Python Playwright можно выполнить:

```sh
python3 test/ui-browser.py --browser /usr/bin/chromium --output /workspace/artifacts/agent-ui
```

Проверяются реальные Chromium desktop/mobile страницы, создание/исполнение тестовой очереди, ожидание Windows, автопереходы по зависимостям, отчёты, блокер, потеря подтверждения отправки, перезагрузка черновика, XSS-текст и диалог. Переключение проектов проверяет отдельные очереди/память/черновики, повтор без дубля после потери подтверждения, задержанный ответ прежнего проекта и отказ устаревшей привязке. Executor — protocol fixture; модель не вызывается. Node-only CI не устанавливает браузерные зависимости. Проверка настоящего Codex через панель остаётся отдельной приёмкой после устранения внешнего блокера.
