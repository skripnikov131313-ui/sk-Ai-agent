# Проектная память и проверенные приёмы

`MEMORY.json` хранит предпочтения пользователя и небольшой каталог проверенных приёмов. `src/memory.mjs` читает каталог, готовит контекст следующей попытки и считает результаты существующих очередей. Память сохраняется вместе с проектом и не зависит от продолжительности чата.

## Что происходит автоматически

- Перед native запуском Runner читает каталог именно из корня выбранного проекта. Подходящие по платформе записи и предпочтения передаются Codex вместе с задачей. Файл другого проекта не подмешивается.
- В задаче и журнале каждой попытки сохраняются SHA-256 применённого контекста и ID использованных записей. Полный текст памяти в журнал не копируется.
- Из существующих task checkpoints считаются статусы, попытки, дополнительные попытки, принятые пункты плана и файловые приёмки smoke. Для этих метрик модель не вызывается, файлы состояния не изменяются.
- Панель «Память» и `node src/cli.mjs memory` показывают каталог и метрики. На Windows используется `.\agent.cmd memory`. HTTP endpoint только для чтения: `GET /api/memory` с обычной защитой локального UI.

Каталог отсутствует — исполнитель использует прежний контекст проекта. Некорректный каталог останавливает запуск до расходования попытки; его содержимое сохраняется. Просмотр очереди остаётся доступным. После исправления файла задача может стартовать обычным способом. Это предотвращает тихую замену памяти пустым каталогом.

## Как пополняется опыт

1. Воспроизвести ошибку и сохранить её контекст в PROGRESS.md.
2. Исправить причину, добавить необходимую регрессионную проверку и получить её результат.
3. Записать краткие `problem` и `approach`, приложить ссылки `checks` на файлы проверок. При необходимости задать `platforms`: linux, win32, darwin; пустой список подходит всем средам.
4. Проверить каталог, прогнать относящиеся к изменению тесты и сохранить изменение в Git. Для отката записи использовать обычную историю Git с сохранением пользовательской работы.

Этот цикл выполняет разработчик или агент в рамках разрешённой проектной работы. Тексты случайных ошибок, веб-страницы и модельные отчёты не становятся инструкциями автоматически. Новое предпочтение берётся из обратной связи пользователя; `source` сохраняет её происхождение. Первые записи закрепляют просьбы продолжать разрешённый план и не сообщать отдельно об устранённых временных сбоях.

Память улучшает повторное использование проверенных методов. Она не изменяет веса модели и не доказывает рост её качества. Ссылка на тест — основание записи, а не свежий PASS текущей задачи. Loader проверяет структуру и формат ссылок; он не запускает проверки при каждом чтении. Test suite проверяет наличие файлов ссылок в текущем checkout.

## Формат и ограничения

Версия 1 содержит только `version`, `preferences` и `lessons`. Предпочтение: `id`, `rule`, `source`. Приём: `id`, `title`, `problem`, `approach`, `platforms`, `checks`. Все поля обязательны, неизвестные отклоняются. ID уникальны внутри своей группы.

До 8 предпочтений, до 12 приёмов, до 5 ссылок на тесты в каждой записи. Каталог — обычный UTF-8 JSON файл до 64 КиБ, подготовленный JSON контекст — до 12000 символов. Символические ссылки, выход за проект, управляющие символы, пути с traversal, неизвестные платформы и распознаваемые форматы credentials отвергаются. Фактическое чтение ограничено по размеру даже при изменении файла другим процессом. Каталог не предназначен для секретов; фильтр форматов не способен распознать произвольный секрет.

Память содержит данные более низкого доверия, чем текущие инструкции и разрешения. Она не может расширить sandbox, включить публикацию, оплату, установку ПО или доступ к чужому проекту. Runtime продолжает использовать штатные workspace-write/cwd/timeout и проверку требований. API изменения памяти, удаления истории или редактирования AGENTS.md из браузера не добавлены. Процессы самого владельца остаются внутри существующей доверенной границы локального UI.

## Метрики

`outcomes.queue` и `outcomes.plan` считаются раздельно из сохранённых баз:

| Поле | Смысл |
| --- | --- |
| `total`, `byStatus` | Записи и сохранённые статусы, без текстов задач и raw отчётов |
| `attempts`, `extraAttempts` | Число попыток; дополнительные — после первой попытки каждой задачи |
| `verifiedFiles` | Успешные записи smoke с ранее сохранённой независимой файловой приёмкой |
| `acceptedPlanItems` | Пункты work, принятые по согласованности checkbox и модельного отчёта |
| `contradictoryReports` | Старые completed-записи с блокерами; не учитываются как успех в панели памяти |

Метрики отражают текущую историю файлов очереди, а не постоянный внешне защищённый аудит. Файлы не проверяются заново при чтении метрик. Файловая приёмка отличается от сообщения исполнителя и от приёмки произвольного кода. Анализ не передаёт goals, session ID, PID/host, run tokens или blockers в память/метрики.

## Проверки

`test/memory.test.mjs` проверяет границы JSON, форматы ссылок, фильтрацию по платформе, повторяемый fingerprint, отсутствие утечки исходных данных в ошибках/метриках, отказ symlink, read-only поведение, блокировку некорректной памяти без расхода попытки и настоящий subprocess fixture с контекстом/сохранением версии. При отсутствии права создавать file symlinks этот один тест явно skipped; права системы не меняются.

HTTP tests проверяют read-only endpoint и восстановление после повреждённой памяти. Chromium проверяет третий раздел панели, предпочтения, числа, HTML как текст, переход назад к очереди и узкий viewport. Native executor в тестах — fixture без модели. Реальную полезность памяти в задачах Codex следует оценивать отдельно после отложенной авторизации.
