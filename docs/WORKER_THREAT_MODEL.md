# Граница Cloud ↔ Windows worker

Статус: проект следующего этапа, не развёрнутый транспорт. Текущая маршрутизация проверяет требования внутри одной доступной очереди. Этот документ фиксирует модель угроз до подключения ПК, как требует план проекта.

## Цель и доверенные стороны

Пользователь задаёт конечный результат и разрешённый план. Cloud выполняет подходящие задачи; выключенный Windows-компьютер оставляет локальные задачи в ожидании. Локальный процесс исполняет только явно адресованные windows/windows-gui задачи в заранее выбранном репозитории.

Доверенные настройки: разрешённые владельцем репозитории, локальная привязка repo ID → root, native Codex и правила sandbox, состояние попыток и ручное разрешение GUI. Текст задачи, сайты, модельный ответ и скачанный артефакт не предоставляют новых полномочий. Browser остаётся отдельным продуктом; его страницы не получают доступ к worker API.

В доверенную границу входит владелец ОС и его локальные процессы. Защита от компрометации Windows-администратора или самой Cloud-платформы этим транспортом не обеспечивается.

## Условие выбора транспорта

Перед реализацией подтвердить поддерживаемый API, способ авторизации, устойчивое хранение, lifecycle фонового процесса, ограничения и расходы. ChatGPT/Codex Plus не считать API-кредитом. Не опираться на скрытые backend endpoints, перехват browser cookies, копирование auth.json или извлечение существующих Codex credentials.

ПК инициирует исходящее HTTPS-соединение с проверкой TLS к выбранному сервису. Входящий PowerShell/RDP и публичное размещение текущего loopback UI не используются. Правила интернет-доступа, pairing и новые секреты не меняются скрыто. Настройка транспорта с неизвестной стоимостью или новыми полномочиями требует отдельного решения владельца после подготовки конкретной реализации.

Каждый worker получает отдельную отзываемую идентичность с доступом к определённым repo ID и типам задач. Удалённый отправитель не может передать произвольные root, shell, executable, environment variables, sandbox flags или команды восстановления PID. Сам флаг windows-gui означает требование, а не доступность GUI-инструментов.

## Минимальный контракт задания

Типизированная запись содержит версию, job ID, repo ID, базовый commit, цель, target, зависимости, ID снимка плана, revision и пределы попытки. План фиксируется до запуска. Новые задания не продлевают его автоматически.

Worker локально проверяет allowlist репозиториев, соответствие commit и состояние рабочей копии. Пользовательские изменения сохраняются; удалённое задание не может потребовать reset/clean или установку системного ПО. Windows GUI требует локального opt-in и фактических инструментов. При несовпадении среды задача ждёт без попытки; при обнаруженном блокере возвращается причина.

В тексте задания нельзя надёжно распознать все секреты. Поэтому задачи и отчёты не публикуются автоматически в GitHub issue/branch или общий канал. Сервис хранения должен иметь подходящую границу доступа. Проектные ключи или credentials не входят в envelope и не передаются модели.

## Владение попыткой и сбои

Владелец попытки определяется отдельным attempt ID и атомарным compare-and-swap в устойчивом хранилище. Worker сохраняет checkpoint до native запуска. Повтор доставки того же job/attempt не создаёт второй процесс. PID имеет смысл только на известной машине и не заменяет удалённый протокол владения.

Истечение lease или потеря heartbeat означает неизвестное состояние старого процесса. Само по себе это не разрешает повторное выполнение: выключение сети не доказывает остановку Codex. До подтверждения остановки или безопасной независимой проверки результата повтор остаётся заблокированным. Fencing token защищает запись нового состояния, но не останавливает уже запущенный процесс и не гарантирует exactly-once внешних эффектов.

Локальный предел времени попытки не продлевается входящими сообщениями. Общий бюджет применяется только при явном выборе пользователя. Потеря связи сохраняет результат локально до подтверждённого приёма; состояние не переписывается новым пустым снимком. Поздний отчёт чужой/старой попытки не меняет текущую задачу.

Остановка — запрос конкретной попытке. Worker прекращает native child штатным контроллером и подтверждает checkpoint. Удалённая сторона не получает kill по произвольному PID. Отзыв worker credentials прекращает новые выдачи; для уже выполняющейся задачи нужны остановка или достижение её локального предела.

## Результат и артефакты

Ответ содержит job ID, attempt ID, ожидаемый repo/base commit, структурированный отчёт и ограниченный список артефактов. Приём требует совпадения владельца и версии. Непустые blockers останавливают зависимые задания независимо от заявленного completed. Ненулевой exit или отсутствие корректного отчёта не превращаются в успех.

Артефакты имеют allowlisted относительные имена, ограничение размера и digest. Traversal, symlink, исполняемые вложения и произвольная распаковка отвергаются. Hash подтверждает доставку содержимого, а не правильность кода. Отчёт модели, получение артефакта и независимая приёмка результата различаются явно. Применение изменений поверх нового/грязного checkout требует проверки конфликтов с сохранением пользовательской работы.

Журналы содержат ограниченные события без tool payload, токенов и содержимого страниц. Диагностика получает понятные причины и correlation ID; credentials вводятся только штатным способом и хранятся в выбранном vault/credential store. Память проекта не повышает доверие к входящему заданию и не меняет разрешения.

## Матрица обязательной приёмки

| Ситуация | Ожидаемое поведение |
| --- | --- |
| ПК выключен | Windows-задачи ждут, независимые Cloud-задачи продолжаются |
| Повтор доставки задания | Одна активная попытка, сохранённый ответ возвращается повторно |
| Потеря сети после запуска | Нет конкурирующего запуска только из-за lease timeout |
| Старый worker вернул поздний результат | Новый checkpoint сохраняется; старый ответ не применяется |
| Credentials отозваны | Новые задания не выдаются; активная попытка учитывается отдельно |
| Подмена repo/root/commit | Отказ до native запуска; пользовательские файлы сохранены |
| GUI не разрешён или инструменты отсутствуют | waiting либо blocked с конкретной причиной, без фиктивного PASS |
| completed вместе с blockers | blocked; зависимые задачи не стартуют |
| Повреждённый/слишком большой отчёт или артефакт | Отказ приёма, сохранение диагностируемого состояния |
| Web prompt injection или shell в результате | Данные не меняют типизированный контракт и полномочия |
| Приостановка Cloud во время попытки | Устойчивое состояние и проверка прежнего владельца перед восстановлением |

До выбора реального поддерживаемого транспорта и прохождения этой матрицы нельзя заявлять подключение Windows-ПК, постоянный Cloud scheduler, доставку при выключенном ноутбуке или работу панели с настоящего iPhone.
