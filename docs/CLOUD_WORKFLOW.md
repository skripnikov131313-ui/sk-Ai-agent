# Работа в Cloud и продолжение после обрыва

## Проверенное состояние — 2026-11-14

- Пользователь сообщил о публикации среды с обоими репозиториями.
- В текущей машине доступны `/workspace/sk-Ai` и `/workspace/sk-Ai-agent`, Node.js 24.22.1, Git и Codex CLI.
- После сбоя запуска повторное подключение восстановило терминал. Точная причина приостановки платформой неизвестна.
- `node src/cli.mjs doctor` теперь использует PATH текущей ОС и подтверждает доступную авторизацию. Это не проверяет возможность вложенного исполнения, остаток квоты или API-биллинг.

## Как продолжать

1. Откройте существующую Cloud-задачу в поддерживаемом клиенте. Сам факт открытия другого чата не переносит её локальную очередь.
2. Проверьте доступность машины, `git status --short` и последние `PROGRESS.md` / `TASKS.md` в обоих проектах. Не перезаписывайте существующие изменения. Задача уже изолирована; дополнительный Git worktree без отдельного запроса не нужен.
3. В `/workspace/sk-Ai-agent` выполните `node --test test/*.test.mjs`, `node src/cli.mjs doctor` и `node src/cli.mjs list`.
4. В `/workspace/sk-Ai` выполните `node --test tests/*.test.mjs`. Для UI: `python3 -m http.server 8000 --bind 127.0.0.1 --directory src`. После восстановления машины сервер нужно запускать заново.
5. Продолжайте следующую незавершённую задачу, сохраняя фактические результаты в Git и документах. Локальный commit не равен push. Внешняя публикация — отдельное явно разрешённое действие.

## Если телефон или ноутбук потерял связь

Вычисления Cloud не исполняются на телефоне или ноутбуке. Отключение клиента не означает обязательную остановку уже выполняющейся задачи. Однако бесконечная работа не гарантируется: действуют ограничения сессии, квоты, приостановка среды и доступность платформы. Здесь нет отдельного фонового scheduler, службы уведомлений или автоматического retry. Живые процессы не являются частью гарантированно восстановленного снимка.

Сохраняемые контрольные точки помогают продолжить работу, но не гарантируют возобновление конкретного процесса. Нельзя повторно запускать задачу, пока не проверено, что её старый исполнитель остановлен. Восстановление локального worker описано в README. Продолжение после выключения конкретного iPhone/ноутбука следует проверить в клиенте; тестами внутри контейнера оно не подтверждается.
