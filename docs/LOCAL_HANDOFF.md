# Контекст для локального Codex на Windows

Пользователь просит выполнять разрешённую работу самостоятельно. Он не хочет быть посредником, по очереди вводящим команды и пересылающим вывод между Windows и Cloud. Этот файл передаёт контекст новой локальной сессии официального Codex CLI.

## Что уже подтверждено

- Репозиторий: `skripnikov131313-ui/sk-Ai-agent`, ветка `cloud/agent-reliability`.
- Windows x64, Node.js `26.13.1`, Git, native Codex CLI `0.168.0`, существующая авторизация ChatGPT.
- WinGet package executable работает по полному пути. Portable alias `codex`/`codex.exe` не доступен; Agent уже умеет находить native binary внутри стандартного пакета WinGet. Повторная установка не требуется.
- Реальная задача `0b7edf0d-5920-4d51-8a17-f4f0c80b6567` создала и проверила свежий файл: `Smoke PASS`, completed, сохранён session ID, acceptance.verified=true.
- После исправления конкурентного EPERM на tasks.json.lock пользователь прислал результат полного suite: **55 tests, 55 passed, 0 failed, 0 skipped** на своём Windows/Node.js 26. Это проверка версии `8a0f508`.
- CI также проверяет Windows Node 24/26 и Linux Node 24. Тесты используют имитатор; положительный реальный smoke описан отдельно выше.

## Следующие действия

1. Прочитай AGENTS.md, TASKS.md и актуальный PROGRESS.md. Проверь `git status`, сохрани пользовательские изменения. Используй эту рабочую копию; дополнительный worktree создавай только по прямому запросу пользователя.
2. Выполняй разрешённые Windows-проверки и диагностику через собственные инструменты. Уже подтверждённые smoke и 55 tests повторяй при изменениях, новой ошибке или конкретной необходимости.
3. Ещё не подтверждены реальные interrupt/resume с Codex, отрицательные границы sandbox, GUI, мобильное продолжение и квоты. Выбери выполнимые локально проверки. Сохраняй точные доказательства; fixture-тесты не заменяют реальный сценарий.
4. Работай в корне этого репозитория. Если проверка требует действий вне корня, системной установки, административных прав, публикации или новых расходов, подготовь конкретное описание и запроси нужное разрешение. Не меняй политики и не обходи sandbox/approvals.
5. Cloud остаётся основным маршрутом разработки. Browser — отдельный продукт и репозиторий; этот worker не даёт ему произвольный доступ к системе. Параметры WebView2/CEF и облачного Qwen пока открыты.

## Итог

Обнови документы только проверенными результатами. Запиши `.skai-agent/local-handoff-report.md` с выполненной работой, checks passed/failed/blocked/unrun, изменёнными файлами и точными блокерами. Не записывай ключи, auth-файлы или коды входа. Сохранить изменения локальным коммитом можно; публикация требует отдельного разрешения в этой локальной сессии.

Это самостоятельная локальная сессия, а не удалённое подключение Cloud-чата к ноутбуку. Её вывод/очередь автоматически в Cloud не синхронизируются. Сессия launcher ограничена 10 минутами; история официального Codex хранится его штатным механизмом. Выход из клиента с кодом 0 означает закрытие клиента и не является подтверждением завершения задач.
