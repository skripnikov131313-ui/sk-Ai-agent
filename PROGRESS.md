## 2026-11-14 — надёжность worker в опубликованной Cloud-среде

- Пользователь подтвердил публикацию, оба checkout доступны. После сбоя запуска терминал восстановился; сетевой/платформенный первоисточник сбоя не установлен. Предыдущие настройки не применялись повторно, публикация не выполнялась.
- Doctor исправлен для Linux: Node/Git/Codex обнаруживаются, текущая CLI-авторизация подтверждена без вывода её содержимого. Native executable выбирается без shell-обёртки.
- Очередь получает файловую блокировку, fsync и атомарную замену. Параллельные процессы не затирают задачи, повреждённая база не заменяется пустой. Снятие устаревшей блокировки — отдельная команда для остановленного владельца.
- Runner выделен в модуль: session ID сохраняется сразу, каждая попытка получает отдельный файл, статус/отчёт/ошибка сохраняются в очереди. Запрещены одновременный повторный запуск, невалидные ID и более трёх попыток. Ненулевой exit или отсутствующий новый отчёт не становится успехом.
- Timeout и SIGTERM останавливают отдельную POSIX-группу; при игнорировании SIGTERM следует SIGKILL. Сохраняется interrupted; recover/resume только вручную и при подтверждённой остановке. Windows taskkill-ветка подготовлена, ещё не проверена на Windows.
- Raw tool payload/login/stderr не сохраняются в журнал. Ограничены диагностические буферы/строки/количество событий, известные форматы credentials удаляются из финального отчёта и ошибки.
- Подготовлен CI Linux/Windows с закреплёнными Actions/Node и JUnit artifact. Отправки в GitHub, запуска Actions и расходов не было; SHA Actions сверены с официальными Git-тегами.
- Протокольные проверки используют имитатор, не вызывают модель и не доказывают реальный Codex sandbox. Настоящее изменение файла вложенным Codex, Windows/mobile acceptance и квоты остаются открытыми.
