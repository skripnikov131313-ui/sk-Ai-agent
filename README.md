# Sk/Ai Agent

Локальный ограниченный исполнитель задач на базе уже авторизованного Codex CLI. Для длительной работы с телефона и при выключенном ноутбуке основной маршрут — **Codex Cloud**, после публикации Cloud environment с репозиториями. Этот Agent не создаёт второй LLM runtime или API-биллинг.

## Локальная проверка

Если Node.js доступен в PATH:

```cmd
node src\cli.mjs doctor
node src\cli.mjs list
node --test test\*.test.mjs
```

Если Node есть только в составе Codex Desktop, из корня репозитория используйте:

```cmd
agent.cmd doctor
agent.cmd list
agent.cmd run <id>
```

Launcher требует Node.js 24 или новее. Он ищет runtime через явный `SKAI_NODE_EXE`, PATH, стандартные папки Node.js и пакет Codex Desktop. Имена MSIX с точкой и подчёркиванием перед версией поддерживаются. Launcher ничего не устанавливает и не меняет системные настройки. Путь к внутреннему runtime может меняться при обновлениях приложения; наличие самого Codex Desktop не гарантирует доступность отдельного `node.exe`.

Если Node не найден, установите его в Windows самостоятельно:

```powershell
winget install --id OpenJS.NodeJS.LTS --exact --source winget
```

Закройте PowerShell, откройте заново и проверьте `node --version`, затем из папки проекта выполните `.\agent.cmd doctor`. Для существующего нестандартного runtime можно задать путь только для текущей сессии:

```powershell
$env:SKAI_NODE_EXE = 'C:\путь к Node\node.exe'
.\agent.cmd doctor
```

Если заданный путь отсутствует или выбранный Node несовместим, launcher завершится с явной ошибкой. Он не подменяет ошибочный override другим runtime.

## Текущие ограничения

- Задачи исполняются на этой машине; ноутбук должен быть включён.
- Успех принимается только по новому структурированному отчёту текущей попытки (`completed` / `blocked` / `failed`). Коды CLI: 0 — completed, 2 — blocked, 1 — невалидный отчёт/failed, 124 — timeout, 130 — остановка пользователем; ненулевой код самого Codex сохраняется.
- Один запуск ограничен десятью минутами; до трёх попыток на задачу, повторы только вручную.
- Доступ Codex ограничен `workspace-write` репозитория.
- UI чата, Cloud API и автосинхронизация с мобильным устройством не реализованы.
- Реальное выполнение вложенным Codex ранее блокировалось в Windows Desktop (`registered Core launch requires an installed app`). Текущие интеграционные тесты используют имитатор CLI, без вызовов модели. Это не проверка реального Codex sandbox.
- На Windows требуется native `codex.exe`/`codex.com` в PATH. Обёртки `.cmd`/`.bat` обнаруживаются, но не исполняются через shell автоматически.

## Cloud и потеря связи

Оба репозитория подключены к опубликованной среде, текущая облачная машина проверена. Для разработки не нужно запускать второй Agent: используйте задачу Codex Cloud. Компьютер пользователя может быть выключен, но Cloud-сессия ограничена временем, квотами и жизненным циклом машины. Публикация среды не создаёт круглосуточный scheduler. Конкретные квоты аккаунта и продолжение с iPhone ещё не проверены.

Локальные файлы `.skai-agent` не синхронизируются между разными Cloud-задачами автоматически. Незакоммиченные/неотправленные изменения также нельзя считать сохранёнными в GitHub. Инструкции продолжения: [`docs/CLOUD_WORKFLOW.md`](docs/CLOUD_WORKFLOW.md).

## Восстановление worker

`node src/cli.mjs show <id>` показывает сохранённый статус, ID сессии и путь к отчёту. ID сессии записывается при получении `thread.started`, до завершения процесса. Каждая попытка получает отдельный каталог отчёта. Команды запускайте из корня этого репозитория.

При обычной остановке Ctrl+C/SIGTERM worker останавливает дерево процессов и сохраняет `interrupted`. После аварийного завершения:

1. Остановите другие локальные worker. Если очередь сообщает о блокировке, выполните `node src/cli.mjs recover-store`; команда снимет блокировку только для подтверждённо остановленного процесса этой машины.
2. Выполните `node src/cli.mjs recover <id>` для оставшейся `running` задачи. Команда требует известные PID worker и Codex и проверяет, что оба остановлены.
3. Проверьте `show`, затем явно вызовите `node src/cli.mjs resume <id>`. Если ID сессии не был получен, создайте новую задачу после проверки результатов предыдущей.

Восстановление на другой машине или без известных PID намеренно не выполняется автоматически: сначала нужно подтвердить, что старый исполнитель больше не работает. Самопроизвольных повторов нет. На POSIX останавливается отдельная группа процессов; на Windows используется `taskkill /T /F`. Процессы, самостоятельно покинувшие группу, этим механизмом не контролируются; границы реального Codex sandbox проверяются отдельно.

Тесты: `node --test test/*.test.mjs` (Linux shell). В PowerShell: `node --test (Get-ChildItem test/*.test.mjs).FullName`. Workflow проверяет Linux и Windows и сохраняет JUnit-результаты. [Первый реальный запуск](https://github.com/skripnikov131313-ui/sk-Ai-agent/actions/runs/43706317987) для коммита `451e0c5` успешно завершил оба задания; GitHub показывает оба артефакта результатов. Это проверка worker с имитатором Codex, без вызовов модели.
