# Проверки

## Автоматические проверки (Node.js 24)

- `node --test test/*.test.mjs` из корня проекта в Linux; PowerShell: `node --test (Get-ChildItem test/*.test.mjs).FullName`.
- Хранилище: создание и валидация задач, конкурентные изменения из одного/нескольких процессов, сохранение повреждённой базы без перезаписи, восстановление только остановленного владельца блокировки.
- Runner с имитатором CLI: обязательные sandbox/cwd аргументы, свежий отчёт каждой попытки, blocked/failed/невалидный JSON/ненулевой exit, сохранение session ID до завершения, resume с нужным ID, запрет двойного запуска/лишних попыток, отсутствие потери финальной JSONL строки, ограничение размера строки и фильтрация payload журналов.
- Отказоустойчивость: timeout и остановка потомка, игнорирующего SIGTERM в POSIX; пользовательская SIGTERM с сохранением interrupted и удалением обработчиков; ENOENT/EPIPE при отсутствующем executable.
- Приватность: распознаваемые credentials удаляются из отчёта/ошибки; raw login/stdout/stderr не попадают в сохранённую диагностику. Это не универсальное обнаружение произвольных секретов.
- `node src/cli.mjs doctor` и `node src/cli.mjs list` проверяют текущую установку. Отчёт doctor подтверждает авторизацию только по exit status login, а не по содержимому ответа.
- `.github/workflows/check.yml` выполняет те же проверки на Linux/Windows и сохраняет свежий JUnit artifact. Само наличие YAML не подтверждает запуск CI.

Имитатор намеренно не вызывает модель и не проверяет изоляцию настоящего Codex. Он записывает контрольный файл только в временную папку теста. Проверки timeout/дерева процессов фактически исполнены на Linux и в Windows CI: [run 43706317987](https://github.com/skripnikov131313-ui/sk-Ai-agent/actions/runs/43706317987), оба задания успешны. Содержимое GitHub logs/artifacts из Cloud не прочитано; для локального JUnit ранее проверены 27 testcase без failures/errors.

## Реальное исполнение (пока не пройдено)

- В разрешённом локальном Windows/Codex контексте: создать задачу с ограниченным изменением тестового файла, проверить фактический diff, structured report и session ID.
- Прервать выполнение, проверить отсутствие дочерних процессов, затем явно восстановить и продолжить задачу.
- `agent.cmd list` должен работать даже если `node` не в PATH. Native Codex executable должен быть доступен отдельно; shell batch launcher автоматически не запускается.

- аварийное прекращение убивает весь процесс Codex CLI.
