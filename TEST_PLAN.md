# Проверки

## Автоматические проверки (Node.js 24)

- `test/routing.test.mjs`: валидация/canonicalization требований, зависимости только на существующие задания, отказ direct run/resume при несовместимости без расхода попыток и потери сессии, Windows GUI opt-in и совместимость старой базы. Внедрённый профиль Windows проверяет только протокол; настоящая GUI-приёмка не заявляется.
- HTTP queue: неизменяемые требования входят в idempotency, клиент не задаёт worker profile; независимые задачи проходят мимо Windows waiting, зависимые запускаются после completed независимо от порядка JSON, all-waiting освобождает lock без executable. `work` проверяет метки Windows/GUI, отсутствие повторных попыток в ожидании и дальнейшую обработку на подходящем fixture profile.
- `node --test test/*.test.mjs` из корня проекта в Linux; PowerShell: `node --test (Get-ChildItem test/*.test.mjs).FullName`.
- Хранилище: создание и валидация задач, конкурентные изменения из одного/нескольких процессов, сохранение повреждённой базы без перезаписи, восстановление только остановленного владельца блокировки.
- Runner с имитатором CLI: обязательные sandbox/cwd аргументы, свежий отчёт каждой попытки, blocked/failed/невалидный JSON/ненулевой exit, сохранение session ID до завершения, resume с нужным ID, запрет двойного запуска/лишних попыток, отсутствие потери финальной JSONL строки, ограничение размера строки и фильтрация payload журналов.
- Противоречивые completed/failed с непустыми blockers: итог задачи blocked, исходный отчёт сохранён, нет автоповтора или запуска следующих задач batch. Старый completed с блокерами не разрешает зависимый run/resume; отказ не расходует попытки и сохраняет сессию.
- Отказоустойчивость: timeout и остановка потомка, игнорирующего SIGTERM в POSIX; пользовательская SIGTERM с сохранением interrupted и удалением обработчиков; ENOENT/EPIPE при отсутствующем executable.
- Приватность: распознаваемые credentials удаляются из отчёта/ошибки; raw login/stdout/stderr не попадают в сохранённую диагностику. Это не универсальное обнаружение произвольных секретов.
- `node src/cli.mjs doctor` и `node src/cli.mjs list` проверяют текущую установку. Отчёт doctor подтверждает авторизацию только по exit status login, а не по содержимому ответа.
- `.github/workflows/check.yml` выполняет те же проверки на Linux/Windows и сохраняет свежий JUnit artifact. Само наличие YAML не подтверждает запуск CI.
- `test/launcher.test.mjs` запускается только на Windows: фактически исполняет копию `agent.cmd` в изолированной папке с настоящим Node.exe. Проверяет PATH, стандартную установку без PATH, MSIX с подчёркиванием, явный путь с пробелами и `&`, передачу аргументов/exit code и сообщения при отсутствии runtime. Системные Node-папки тесты не меняют; тестовые файлы находятся в игнорируемом `.skai-agent/test-tmp`. На Linux эти семь проверок отмечены skipped, а не passed.
- `test/codex-discovery.test.mjs`: реальные файловые lookup в fixture-каталогах для WinGet alias/пакета x64/ARM64, исключение helper-файлов/других пакетов/директорий, обработка неоднозначности и explicit override. Fixtures не исполняются как реальные Codex binaries.
- `test/smoke.test.mjs`: protocol fixture создаёт правильный свежий файл, неправильный файл, не создаёт proof либо возвращает blocked. Приёмка обязана отвергать completed без правильного файла. Проверяется сохранение результата в очереди и отказ от proof-пути вне проекта. Модель здесь не вызывается.
- `test/file-lock.test.mjs`: временные Windows EPERM/EACCES/EBUSY при exclusive open, восстановление после освобождения lock другим владельцем, конечный отказ при устойчивой ошибке, сохранение существующего lock, отсутствие повторов для Linux EPERM и несвязанных I/O ошибок. Инъекции ошибок проверяют конкретный сбой без изменения прав файлов.

Имитатор намеренно не вызывает модель и не проверяет изоляцию настоящего Codex. Он записывает контрольный файл только в временную папку теста. Проверки timeout/дерева процессов фактически исполнены на Linux и в Windows CI: [run 43706317987](https://github.com/skripnikov131313-ui/sk-Ai-agent/actions/runs/43706317987), оба задания успешны. Содержимое GitHub logs/artifacts из Cloud не прочитано; для локального JUnit ранее проверены 27 testcase без failures/errors.

## Реальное исполнение

`test/ui-server.test.mjs` запускает настоящий Node HTTP server и проверяет сохранение/idempotency, последовательный finite snapshot, stop с остановкой child, bounded retries/resume, отсутствие raw session ID, сохранение повреждённой базы и отказ восстановления чужого/live worker. Проверяются Host/Origin/Sec-Fetch-Site, обязательный заголовок, отсутствие CORS, CSP, тело запроса и отсутствие произвольного exec/file endpoint. Отдельно настоящий CLI запускает paused-сервер на свободном порту.

`test/ui-browser.py` — опциональная проверка Chromium desktop/mobile с fixture executor: потеря подтверждения после сохранения, изменение/повторная отправка, очередь/отчёт/блокер, черновик после reload, HTML как текст, диалог и отсутствие горизонтального overflow. Эта проверка выполнена локально в Cloud; Node CI не устанавливает Playwright и не вызывает модель.

`test/background.test.mjs` запускает отдельный fixture worker из короткоживущего launcher-процесса и проверяет работу после выхода launcher, отказ второго запуска/восстановления живого worker, кооперативную остановку native child, сохранение очереди, завершение и повторный старт без дублирования, сохранение ошибок и отказ действий с чужим host. На Windows cleanup ждёт закрытия процесса и его log handle. Это проверка транспорта процесса, без вызова модели и без обещания пережить приостановку managed Cloud.

`test/work.test.mjs` также проверяет полный план из десяти пунктов без прежнего cap=8, null deadline по умолчанию и явно заданный бюджет свыше четырёх часов.

`test/atomic-file.test.mjs` проверяет ограниченные повторы атомарного rename при Windows sharing errors, сохранение старого файла до успеха и исходной ошибки при устойчивом отказе. Destination не удаляется для обхода ошибки. Отдельно проверяются немедленные отказы Linux EPERM и Windows ENOENT.

`test/work.test.mjs` отдельно проверяет последовательный переход без ввода пользователя, ограниченный resume при failed/timeout/непринятом отчёте, восстановление пропущенной приёмки после сбоя, отсутствие повторов completed/blocked и повторного расходования попыток, конечный снимок плана, лимит пунктов/общего времени, abort с остановкой цепочки, отказ второго диспетчера и запрет повторного запуска running. Это имитация CLI без модели.
