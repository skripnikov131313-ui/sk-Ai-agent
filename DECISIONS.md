# Решения

## D-0001 — Codex Cloud для задач, которые должны переживать выключение ноутбука

- Статус: среда опубликована пользователем; доступ к обоим репозиториям и исполнение тестов в Cloud подтверждены 2026-11-14. Непрерывная работа при отключении клиента и мобильное продолжение ещё не испытаны.
- Причина: OpenAI описывает изолированные Cloud workspaces с продолжением desktop/web/mobile и сохранением состояния при выключенном локальном компьютере.
- Источники: [`docs/FEASIBILITY.md`](docs/FEASIBILITY.md).

## D-0002 — Не строить собственный Cloud runtime на API до оценки расходов

- Статус: принято.
- Причина: план ChatGPT/Codex не равен API биллингу. Собственная orchestration API может повлечь отдельные расходы и хранение ключей.

## D-0003 — Windows local worker остаётся дополнением

- Статус: принято для MVP.
- Причина: локальный код нужен только для задач, которые не выполняются в опубликованном Cloud environment; он не работает, когда ПК выключен.

## D-0004 — Явное восстановление и отдельные отчёты попыток

- Статус: реализовано и проверено протокольными тестами в Linux.
- ID сессии сохраняется сразу, изменения очереди сериализуются файловой блокировкой, данные записываются через fsync и атомарное переименование.
- Каждая попытка имеет новый файл отчёта; старый `completed` не подтверждает новый запуск. В обычной очереди до трёх явных попыток на задачу; отдельный выбранный режим `work` допускает ограниченный retry по D-0006.
- `recover` не трогает живой процесс, неизвестный PID или другую машину. Переход на новую Cloud-машину не является доказательством остановки старого исполнителя.
- Диагностические ответы Codex/login не сохраняются. Журнал содержит ограниченный набор имён событий, без payload инструментов; распознаваемые форматы credentials удаляются из сохранённого отчёта. Произвольный секрет невозможно надёжно определить по формату: не вводить секреты в задачу.

## D-0005 — Windows CI готовится отдельно от публикации

- Статус: ветка отправлена с разрешения пользователя; run `43706317987` для `451e0c5` успешно прошёл на Linux и Windows. Это protocol integration tests, не реальное выполнение модели.
- Linux/Windows test matrix без вызовов модели, минимальные права, закреплённые Actions, JUnit artifact. Квоты не предполагаются без проверки.

## D-0006 — Конечный диспетчер вместо повторных сообщений «дальше»

- Пользователь запросил автономное исполнение и отклонил общий таймер 60 минут. `work` проходит весь исходный план без общего таймера по умолчанию; --minutes и --max-tasks выбираются явно. Сохраняются три попытки на пункт, сессии и прогресс. `work-start` запускает отдельный процесс, `work-stop` останавливает его с сохранением очереди.
- Новые пункты не продлевают текущий запуск; completed не повторяется, blocked не повторяется без явной опции, отсутствие корректного отчёта останавливает дальнейшие вызовы. Приёмка сверяет checkbox и отчёт, не объявляя произвольный модельный результат независимо доказанным.
- Постоянный Cloud scheduler, удалённое управление ПК и синхронизация состояния не развёрнуты. [Пределы и восстановление](docs/AUTONOMOUS_WORK.md).

## D-0007 — Локальное окно задач с существующим executor

- Пока пользователь отложил применение сети/Cloud login, разработка продолжается на части, которую можно проверить локально. Добавлена панель без новых зависимостей: собственная очередь задач, детальные отчёты и последовательный controller поверх штатного Codex adapter.
- Постановка задачи сохраняет её; отдельный запуск фиксирует всю текущую очередь. Успешные задачи переходят дальше автоматически; реальный блокер останавливает запуск. `work` и его очередь остаются отдельными и видны в панели для чтения.
- Панель привязана к loopback. Идентификация удалённого пользователя и доступ с телефона отложены; совместимость узкого viewport и фиктивный executor не выдаются за реальный mobile/Cloud AI.

## D-0008 — Явные требования и зависимости перед межмашинным транспортом

- Задачи получают target и до 32 существующих зависимостей своей очереди. Только completed предшественник разрешает запуск; требования неизменяемы через API. Старые задания совместимы с current.
- Проверка есть в store/queue/work и повторяется атомарно в native adapter. Windows/GUI задачи в неподходящей среде ждут без вызова модели и расхода попыток. Независимые задачи и освободившиеся зависимости проходят в том же конечном batch.
- Windows GUI требует явного --desktop в локальном процессе. Этот флаг не подтверждает наличие инструментов и не меняет sandbox. Протокольные тесты с внедрённым Windows profile не объявляются приёмкой рабочего стола.
- При отсутствии готовых задач batch освобождает lock и завершается waiting. Скрытый scheduler, публичный endpoint, удалённый shell и синхронизация ПК не добавляются. [Контракт и применение](docs/TASK_ROUTING.md).

## D-0009 — Проверенная проектная память вместо автоматического превращения ошибок в инструкции

- Предпочтения из обратной связи и приёмы после регрессионной проверки хранятся в versioned MEMORY.json. Перед попыткой применяется ограниченный контекст с fingerprint; ссылки на старые тесты не объявляют текущую задачу принятой.
- Метрики считаются локально из task checkpoints, без вызовов модели, публикации raw отчётов и автоматического изменения AGENTS/полномочий. Просмотр доступен в CLI/панели; сырая ошибка или веб-страница не становится правилом сама.
- Каталог отсутствует — прежнее поведение. Каталог повреждён — отказ до расхода попытки с сохранением данных. Формат и цикл проверки: [PROJECT_MEMORY](docs/PROJECT_MEMORY.md).

## D-0010 — Переносимый Windows пакет с обычными Git/sandbox проверками

- Пакет включает официальный закреплённый Node и LICENSE, без системной установки, клонирования или копирования пользовательских credentials. Источник — точный чистый Git commit; артефакт хранится отдельно от checkout.
- Перед первой задачей пакет создаёт собственный локальный Git root, сохраняя проверку Codex. Родительский checkout не используется как неявная рабочая область; runtime/очередь игнорируются. Существующий репозиторий и пользовательские файлы сохраняются.
- Проверка дистрибутива на Windows выполняется после core tests: launcher, bundled Node, Git bootstrap, paused UI/memory, затем загрузка артефакта. Модельная и пользовательская GUI приёмки остаются отдельными. [Контракт сборки](docs/PORTABLE_WINDOWS.md).
